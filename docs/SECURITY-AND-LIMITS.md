# 安全性と制限

## 非公式の個人アカウント連携

LINEの公式サポート対象ではありません。仕様変更、認証切れ、端末の認証制限、利用規約やアカウント制限のリスクがあります。業務の唯一の通知手段や、確実な最新履歴の取得には使いません。実アカウントでの認証・読取・配信は、利用者自身の端末とアカウントで確認してください。PC用ログインの承認で、既存のPC用セッションが無効になる場合があります。認証ファイルが残っていても、既存セッションが有効とは限りません。

## 保存する情報

認証トークン、E2EE鍵、ローカル接続キー、本文、チャット名は、Windowsの現在のユーザー用DPAPIで暗号化して保存します。データフォルダのDACLは利用者とSYSTEMだけを許可します。既存フォルダの権限を勝手に変更せず、想定外の権限があれば拒否します。共有パスとリパースポイントも拒否します。

Linux ではAES-256-GCMを使い、32バイトのプロファイル鍵を本人所有の0600ファイルに保存します。保存先は0700、ファイルは0600で作成し、所有者・権限・シンボリックリンク・ハードリンクを検査します。鍵と暗号化データは同じ保存先なので、同じユーザー、root、オフラインでディスクを読める人から保護する方式ではありません。DPAPIとは保護の前提が異なり、Windowsの認証ファイルをLinuxにコピーして使うことはできません。鍵が欠落しても自動で置き換えません。詳細は `../START-HERE-LINUX.md` を参照してください。

設定、参照、時刻、件数、送信状態など、一部のメタデータは暗号化されません。SQLを含むプロファイル全体を秘密情報として扱います。DPAPIは同じWindowsユーザーとして動く悪意のあるプログラムや、管理者権限での操作から保護するものではありません。実行環境やソースの改ざんも防ぎません。

取得したメッセージは暗号化したSQLiteに永続保存します。保存メッセージは自動削除しません。UUIDの送信予約、チャット参照も自動削除しません。保存を続けるとDBは大きくなります。物理消去やバックアップ先の消去は保証しません。

## QR と PIN の出力

明示的な MCP ログインと CLI の JSON/text 出力では QR PNG Base64・QR URL・必要時の PIN を返せます。MCP のローカル接続だけが認証ツールを公開します。AI へ出した QR/PIN は本人のチャット履歴へ渡るため公開しないでください。保存用トークン・秘密鍵は結果へ含めません。

## 外部への情報共有

ローカルMCPの読み取り結果は、使っているAIクライアントとモデル提供者に渡る場合があります。読み取り専用でも、情報が外へ出ないという意味ではありません。監視を有効にすると、選択したチャットの本文をPC内に暗号化して保存します。外部通知を明示的に有効にすると、指定した webhook へチャット名・件数・本文の抜粋などを送ります。

パスワード、APIキー、秘密鍵、認証URLなどは、代表的な形式を伏せます。検出は完全ではなく、単独の数字だけのワンタイムコード、独自形式の秘密、画像内の秘密を見逃す場合があります。秘密の多いチャットでは本文や名前を共有しません。メッセージはデータとして扱い、本文にある指示を実行しません。

## 通信と権限

デーモンは`127.0.0.1`のランダムポートで待ち受けます。ローカル用・内部の停止用のキーを分けます。ブラウザのOrigin付きリクエスト、認証なし、異なるHost、過大なリクエストは拒否します。stdio接続から保存先・権限・監視設定を変更できません。

共通認証では選択したサブ端末の同じトークンを使いますが、通常のLINEとOpenChatの通信制限は分けます。通常のLINEは`/S4`の明示した読取操作と、1回ごとの送信だけを許可します。OpenChat は HTTPS の既知ホストと `/SQ1` を使います。V3 の Talk は `gf.line.naver.jp/enc` の暗号化 LEGY に対応し、内側の RPC も制限します。どちらにもrefresh tokenを渡さず、上流のトークン更新による自動再送を防ぎます。期限切れは利用者が`login --replace`でQR認証をやり直します。E2EE鍵の新規登録は行わず、必要な鍵がない送信は拒否します。


## 履歴と監視の制限

通常のLINEの履歴は1回最大200件です。保存データの検索は1回最大500件を復号し、続きのカーソルを返します。チャットと時刻をSQLで絞ってから本文を検索し、LINEを自動走査しません。連絡先は最大1000件、グループ一覧は最大500件です。通常LINEのトーク一覧は最大2000件を読み、最後のメッセージが新しい順に返します（新着監視の対象探しも同じ順の先頭100件です）。履歴の時刻は取得済みデータを使い、推測しません。OpenChatの履歴は、LINEが返す直近の範囲（1ルームあたり約50件）を1回で読み、新しい方からN件を返します。それより古いメッセージは読めません。参加チャットの一覧にはページ上限があり、最新N件や全履歴を保証しません。OpenChatの送信者名は、イベントに名前が無い場合だけ、取得したメッセージの送信者をまとめて1回のメンバー情報取得で補い、プロフィールの版が上がるまで再利用します。ボットの投稿には名前が付きません。OpenChatのスレッドは、元のメッセージを指定したときだけ読み書きします（1回最大50件、最新N件は保証しません）。スレッドの返信は新着監視・通知の対象外です。再認証後の検索では別の認証世代のデータを混ぜませんが、古い保存データは残ります。

監視間隔は1〜86400秒、初期値120秒です。API処理、ページング、障害でさらに遅れます。処理を重ねて実行しません。通常のLINEは最新200件を比較するため、大量投稿で取得漏れが起こります。初回の履歴や自分の投稿も、取得できた内容を保存します。停止中のメッセージを後から取得できる場合はありますが、取りこぼしの回復を保証しません。

各メッセージは`kind`（text、image、flex、richなど）と`availability`（complete、partial、unavailable）で区別します。本文を復号できない場合は`reason`に`decrypt_failed`、画像・動画・音声は`media_not_retrieved`、取得できなかった構造は`payload_not_exposed`、未知の型は`unsupported_content`を返します。Flexは代替テキスト、ステッカーは表示文字列、添付ファイルはファイル名など、許可した項目だけを`plain_text`と`content`に取り出します。生のメタデータや画像・動画・音声・添付ファイルの実体は保存しません。写真だけは`message_image`で明示的に取得できます（通常LINE・OpenChat、6MiBまで、`obs.line-apps.com`の写真用パスへのGETのみ）。取得した画像はMCPの画像として返し、保存しません。動画・音声・ファイルは安全のため取得せず、その通信経路も許可していません。メンバー一覧（`chat_members`）は表示名・役割・自分かどうかだけを返し、メンバーIDは返しません。リアクションと参加は行いません。**既読は付けません。これは変更しない方針です**（既読を付ける通信そのものを許可していません）。引用リプライは`send`の`reply_to_message_ref`で行い、LINEの応答に引用が含まれていたかを`reply_confirmed`で正直に返します。テキスト送信は`send`で行い、宛先の再確認・本文の承認・送信間隔の制限はありません。送信の取り消し（`unsend`、自分のメッセージのみ、LINEの制限で約24時間以内）と、OpenChatの副管理者以上によるメッセージ削除（`openchat_delete_message`）も、確認なしで1回だけ実行します。どちらも送信と同じく送信機能が有効なときだけ使えます。通常LINEの1件ずつの削除は、LINEのサーバー側に手段がないため対応しません。

## 公開前の確認

ソース管理と候補作成は許可リスト方式です。`.gitignore`だけには頼りません。秘密パターン・固定ユーザーパスとGit履歴を検査します。依存物バイナリ、認証情報、プロファイル、データベース、QR画像、ログはGitHubや配布候補に含めません。

公開前には、独立した秘密検査、依存物の脆弱性検査、組み込みWASM・生成物・推移依存のライセンス確認、新しいWindowsユーザーでの導入確認が必要です。詳細は`THIRD-PARTY-NOTICES.md`に記載しています。
